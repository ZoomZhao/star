# 2026-10-15 项目 Review

范围：Express / SQLite 服务端、React Web、原生 Android、备份恢复、部署脚本和现有测试。修复以数据保护、失败重试和异步状态为先，提取共用逻辑，移除已经停用的桥接依赖。本轮没有连接或修改生产数据，没有部署，也没有安装到用户手机。

## 已修复

| 问题                                                                   | 调整与结果                                                                                                                                                                                               |
| ---------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 编辑模板会删除已生成的未来任务，导致用户快照被重新计算                 | 只新增规则版本；当天、历史和已生成的未来任务全部保留，只有尚未生成的日期使用相应新版本。测试逐字段核对既有记录，覆盖自定义上限 10 次、停用、单次和每周安排。                                             |
| 完整备份逐表读取时可能混入另一连接的写入；恢复前备份与替换之间存在窗口 | 导出使用一致读事务；恢复先在隔离数据库验证，再在同一写事务内保存旧数据并替换。保存失败保留数据与会话；拒绝跨孩子规则归属和不存在的任务来源版本，允许合法的每日单独修改。                                 |
| 更新入口依赖手动备份和不完整核对                                       | systemd 与 Docker 入口共用 `production-data.mjs`：部署前下载并验证可恢复的备份，健康检查后再次备份，按 ID 比较全部数据集合和全部字段；异常保留证据并报错，没有自动恢复旧数据的分支。                     |
| 旧升级脚本会向既有孩子补整套默认模板                                   | `seed-subjects.mjs` 在打开数据库前拒绝运行。三科课内作业升级只添加指定任务，并在同一事务内先保存完整备份；重复执行保留既有版本、快照、自定义设置和账本。                                                 |
| 请求实际成功但响应丢失后，重新登录重试可能重复记账或创建记录           | Web 和 Android 将未决请求按服务器与稳定账号 ID 保存，成功确认前保留编号；切换账号不共享编号。规则、奖励、家庭创建增加可选幂等支持，使用确定性记录 ID，无需新建表或迁移历史数据。旧客户端仍可请求原接口。 |
| Web 的旧请求完成后可能覆盖另一孩子或新会话；退出等待网络               | 请求结果绑定会话、孩子和日期上下文；切换后忽略旧结果。退出立即清理本地会话，旧退出响应不能影响新登录。奖励上下架仅提交状态，保留另一家长刚编辑的详情。                                                   |
| Android 未决编号保存失败后仍可能发请求；旧回调影响新登录；断网无法退出 | 持久化成功才发送请求；请求捕获自身会话，旧回调不能恢复退出前的界面或清除新登录。本地退出立即完成，后台仅撤销捕获的旧令牌。待确认请求存储提取为可独立测试的 `PendingOperationStore`。                     |
| 外部 NFC 启动消息被当作实体卡读卡结果                                  | 外部消息仅导航到扫描页；发星必须由系统前台读卡回调现场读取卡片后触发。保留检测模式、忙碌保护和登录边界，旧启动消息不重放。已有实体卡不用重写；桌面唤起后可能需要移开再碰。                               |
| Android 日期移动依赖设备时区，跨夏令时可能偏一天                       | 日期操作集中到 `ShanghaiDate`，始终按北京时间自然日计算。                                                                                                                                                |

## 可维护性

- 移除已无运行用途的 Capacitor 包和配置，安装依赖总数减少 96 个；保留原生 Android 及 Web 两条清晰构建路径。
- 备份集合名、验证逻辑、生产比较与下载流程共用实现，避免部署脚本各自维护字段白名单。在线验证改为读取完整备份，避免通过 Dashboard 检查而生成每日任务。
- 共用 UUID v5 实现；原 NFC 卡片账本 ID 命名空间和输入协议保持不变，有固定向量回归保护。
- 部署依赖使用项目锁文件，保证已修复的传递依赖进入运行包；新增 `npm run check` 统一执行服务端回归和 Web 构建。

## 维护边界

模板从明天生效，并不意味着覆盖已存在的明天快照。出现“设置回退”报告时，应先对比部署前备份、所有规则版本、生效日期和每日快照；不能通过重写历史制造表面一致。此行为取代历史 Review 中删除未来预览并重建的做法。

升级前已过期且没有账号身份信息的旧 Token 未决请求不能安全归属，保留原键，不猜测分配给后来登录的账号。已保存稳定账号 ID 的新请求可跨重新登录继续安全重试。

`src/App.tsx` 与 Android `MainActivity.java` 仍集中承载多个页面。后续功能开发可按会话加载、规则编辑、任务卡页面逐步提取模块，并保留本轮竞态和数据保护回归；无需为了拆文件同步改动存储模型。备份与生产比较采用完整对象读取，较大数据量时可再单独设计流式导出与分块核对。
